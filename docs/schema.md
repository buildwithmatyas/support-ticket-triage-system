# Support Ticket Schema

This document describes the structure of the Google Sheets database used by the AI Customer Support & Ticket Triage System.

Each incoming support email is converted into a structured support ticket before being stored.

---

# Ticket Fields

| Column | Type | Description |
|---------|------|-------------|
| TicketID | String | Unique ticket identifier generated by the workflow. |
| CustomerName | String | Customer name or sender information extracted from the email. |
| Email | String | Customer email address. |
| Subject | String | Email subject line. |
| Message | Text | Email message snippet used for AI classification. |
| Category | String | AI-generated issue category. |
| Priority | String | AI-generated urgency level. |
| Status | String | Current ticket status. Default: **Open**. |
| CreatedAt | DateTime | Original email timestamp from Gmail. |
| UpdatedAt | DateTime | Timestamp when the ticket was written to Google Sheets. |
| AssignedTo | String | Assigned support agent. Default: **Unassigned**. |
| Source | String | Ticket source. Default: **Gmail**. |

---

# Category Values

The AI classifier assigns exactly one category.

Allowed values:

- Technical
- Billing
- General

The **Category** describes **what the issue is about**, not how urgent it is.

Examples:

| Example | Category |
|----------|----------|
| Website is down | Technical |
| Login problem | Technical |
| Refund request | Billing |
| Incorrect invoice | Billing |
| Business hours | General |
| Feature request | General |

---

# Priority Values

The AI assigns exactly one priority.

Allowed values:

- High
- Medium
- Low

The **Priority** describes **how urgently the issue should be handled**, regardless of its category.

Examples:

| Example | Priority |
|----------|----------|
| Complete website outage | High |
| Payment system unavailable | High |
| Login issue | Medium |
| Refund request | Medium |
| Business hours question | Low |
| Feature request | Low |

---

# Design Decision

## Separating Category and Priority

One of the most important architectural decisions in this project was separating **Category** from **Priority**.

Instead of using **Urgent** as a ticket category, urgency is represented only by the **Priority** field.

This allows tickets such as:

| Category | Priority |
|----------|----------|
| Technical | High |
| Technical | Medium |
| Billing | High |
| Billing | Medium |
| General | Low |

rather than mixing issue type with urgency.

This design avoids conflicting classifications, simplifies routing logic, and more closely reflects how professional help desk systems organize support tickets.

---

## Why Two AI Classification Steps?

The workflow performs two independent AI classification tasks.

The first AI call determines **what the issue is** (Category).

The second AI call determines **how urgent it is** (Priority).

Separating these responsibilities keeps each prompt focused on a single task, improves classification consistency, and makes the workflow easier to maintain and extend.

---

# Workflow Output

For every incoming support email, the workflow automatically generates a structured support ticket containing:

- Ticket information
- Customer details
- AI-generated category
- AI-generated priority
- Ticket status
- Assigned support agent
- Source information
- Creation and update timestamps

This structured dataset can later be used for reporting, dashboards, CRM integrations, or advanced support analytics.
